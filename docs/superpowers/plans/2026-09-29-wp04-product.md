# WP-04 schema-aware product implementation plan

> Execute inline using `superpowers:executing-plans`, one failing-test cycle at a time.

**Goal:** Preserve schema-qualified Oracle entities and resolve supported qualified references while retaining ambiguity and historical snapshot semantics.

**Architecture:** Use the WP-08 occurrence inventory as the authoritative input to typed candidate selection. Retain legacy bare-name maps as conservative compatibility projections. Integrate new Blueprint entities only after separate tests establish project analysis binding and explicit direct-input identity; do not change `source_revision`.

**Tech stack:** Python 3.10–3.13, existing parser/Blueprint/project pipeline, pytest and Ruff.

**Spec:** `docs/design/formslang-3.0/adr/ADR-06-entity-identity.md`, accepted at `f04561a`; master specification SRC-11/12/14, INV-07 and AC-04; implementation-plan WP-04.

## Constraints

- No merge/tag/release, no #23 changes, no product gate closure.
- Preserve historical inventories and older engine meanings; new extraction needs an engine bump.
- No default-schema, overload or approval inference; absent bytes cannot silently receive a durable identity.
- Keep `source_revision` and the three inherited WP-08 gap tests unchanged.
- Coordinate new durable identity with the existing project `analysis_revision`; no private fingerprint substitutes for it.

## Review focus

- Quoted mixed-case components and dots must stay exact and separate.
- Duplicate CREATE/member occurrences must not choose one winner.
- Missing owner/signature/body must remain explicit uncertainty.
- Same names in separate source roots must remain separate candidates.
- Direct and project pipelines must agree on facts while respecting their analysis identity inputs.
