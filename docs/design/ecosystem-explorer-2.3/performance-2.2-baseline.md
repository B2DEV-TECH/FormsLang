# Performance baseline — the 2.2 read path at 500 Forms

Status: **phase 1, measured.** These are the parameters the 2.3 explorer starts
from. They were measured on the unchanged 2.2 engine. They are not targets, and
they make no claim about customer estates.

## 1. Conditions

| Parameter | Value |
|---|---|
| Commit | `6e449a0` (FormsLang 2.2.0 + release evidence) |
| Machine | Windows 11 Pro 10.0.26200, Intel64 Family 6 Model 158, one local disk |
| Python | 3.13.15 |
| Data | Synthetic, generated by `examples/verify/project_corporate_scale.py --forms 500` |
| Profiles | `baseline` (the pre-2.3 fixture, byte-identical) and `ecosystem` (windows, canvases, tabs, a hidden canvas, an unplaced item, literal `OPEN_FORM`, an unsupplied package, a runtime form and an unsupplied form) |
| Sampling | `examples/verify/project_read_samples.py --samples 10` on the saved project: the first call of each operation is discarded, then 10 sequential warm calls per operation in one process |

Limits: one machine, one synthetic project per profile, one full pipeline run
per profile, sequential calls, and no concurrent users. p95 over 10 samples is
close to the maximum and is reported as such.

A first call after reopening the project took 1.6–3.6 s. The traced
allocation peak of one focused System Map call was 310 MB (baseline) and
436 MB (ecosystem).

**Against the spec (§11: p95 of neighbourhood/path queries ≤ 2 s, warm, 500
Forms):** the ecosystem profile is **not met** on the 2.2 read path. Every
focused read is between 2.4 and 2.7 s. The baseline profile is just under 2 s.
That is consistent with a cost that grows with the size of the Blueprint rather
than with the query (§5).

## 5. Where the time goes

Every read costs about the same, whatever it returns: a 7 KB node summary costs
as much as a 213 KB focus map. The cost is fixed per call.

- A `cProfile` of one warm `module_view` on the ecosystem project attributes
  about 86 % of the call to `copy.deepcopy` of the saved assessment. The
  copy is in `formslang/project_assessment.py:124`, inside
  `current_assessment`, and it runs on every projection. JSON decoding of the
  stored Blueprint takes about 8 %. The projection itself
  (`project_projection.module_view`) takes 62 ms of a 7.5 s profiled call.
  (Profiling inflates absolute times; the proportions are what matter.)
- `freshness()` takes a further 2.7–3.1 s. The 2.2 API takes it as an explicit
  argument, so a screen can reuse it. An endpoint that recomputes it per
  request would double the latency.

Consequence for phase 3, not applied here: the explorer's endpoints need a
read-only, revision-bound view of the Blueprint that is built once per
`analysis_revision` and not copied per request, with freshness checked once per
interaction. That is a change to the read path. It is not a change to
`project_store` timeouts or locking.

## 6. The ESTATE map shows no relationships

The ecosystem profile run did not satisfy the scale script's System Map
assertion. The 2.2 ESTATE view ranks nodes by attention (hotspots, risk,
dependency count), and with the default budget it kept **100 of 531 nodes and
0 of 1,125 relationships**. The kept nodes were all MEDIUM-risk Forms with 4–5
dependencies each, and no two of them are related. The baseline profile, with
the same budget, kept 99 of 501 relationships. The ranking scores each node on its own
(dependency count included) and does not consider whether the kept nodes
relate to one another, so whether any relationship survives depends on the data.

The scale script now records this as an observation for the ecosystem profile,
and keeps the assertion for the baseline. The finding drives two contract rules
([contract §8](contract-ecosystem-1.md#8-bounds-and-truncation)): the explorer
is focus-first, and every bounded view reports relations shown versus
available.

## 7. Reproducing

```text
py examples/verify/project_corporate_scale.py --forms 500 --profile ecosystem ^
   --min-findings 5000 --min-relations 5000 --output <dir>
py examples/verify/project_read_samples.py <dir>\run-<id> --samples 10
```

Neither script writes to the repository. The ecosystem run peaked at about
1 GB of process memory on this machine.
